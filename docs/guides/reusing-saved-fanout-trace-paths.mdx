# Reusing saved fanout trace paths

`pcbTracePaths` on [`<fanout />`](../elements/fanout.mdx) preserves saved copper
and lets the rest of the board route from its exits. Keep the electrical
connections in your TSX.

## Capture, edit and replay a fanout phase

1. Run `tsci build board.circuit.tsx`. The CLI prints the paths of replayable
   stage files in `.tscircuit/autorouting-artifacts/<entrypoint-key>/`.
2. Copy the fanout stage's JSON into your source tree before editing; later
   builds can overwrite generated artifacts. Identify the stage by its execution
   order and port selectors, not just `phase-default` in the filename.
3. Edit the routes, import them as shown below, and rebuild to check DRC.

Dogbone capture requires core **0.0.2027+**.
Diagnostic images and solver inputs are not replayable path arrays.

## JSON example

The saved path leaves R1 through a nearby via. Its final via is the exit where
board routing continues to R2.

    </fanout>

    <trace from="R1.1" to="R2.1" />
  </board>
)
`,
  "saved-fanout.json": JSON.stringify([
    {
      connection: "R1.1",
      route: [
        { route_type: "wire", x: -0.51, y: 0, width: 0.2, layer: "top" },
        { route_type: "wire", x: -1.5, y: 0, width: 0.2, layer: "top" },
        { route_type: "via", x: -1.5, y: 0, from_layer: "top", to_layer: "bottom", via_diameter: 0.3, via_hole_diameter: 0.15 },
        { route_type: "wire", x: -1.5, y: 0, width: 0.2, layer: "bottom" },
        { route_type: "wire", x: 1, y: 1, width: 0.2, layer: "bottom" },
        { route_type: "via", x: 3, y: 1, from_layer: "bottom", to_layer: "top", via_diameter: 0.6, via_hole_diameter: 0.3 },

  ], null, 2),

Saved-path imports require core 0.0.1884+ and props 0.0.649+. Check the resolved
versions inside `tscircuit` as well.

## Editing rules

- Use stable port selectors such as `U1.DATA0`. Supply every routing connection
  in the fanout; partial saved fanouts are unsupported.
- Coordinates are in the **fanout's local PCB frame**, in millimeters, with +X
  right and +Y up. Translation and rotation are applied; layer names stay physical.
- Keep the first point at its pad. The last point defines the exit; do not add a
  separate `<fanoutpoint>` for the same port.
- Preserve layer continuity, positive widths and via diameters. A via starting
  in a pad requires `allowViaInPad`; a trailing via exits on `to_layer`.
- Recheck copper clearances after edits. Valid JSON does not imply passing DRC.

| Point | Required fields | Optional fields |
| --- | --- | --- |
| Wire | `route_type: "wire"`, `x`, `y`, `width`, `layer` | — |
| Via | `route_type: "via"`, `x`, `y`, `from_layer`, `to_layer` | `via_diameter`, `via_hole_diameter` |
