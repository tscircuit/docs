## Overview

In this tutorial you will design a **custom ESP32 development board** schematic
from scratch using tscircuit. The design follows the same architecture found in
popular ESP32 dev boards (ESP32-DevKitC, NodeMCU-32S) and mirrors the approach
taught in
[The Hardware Academy's ESP32 PCB course](https://thehardwareacademy.com/courses/tutorial-full-length-how-to-design-a-custom-esp32-pcb/).

Every component uses a **JLCPCB-stockable part number** so the board can be
directly manufactured.

## Circuit Blocks

The design is split into six functional blocks:

| Block | Components | Purpose |
| --- | --- | --- |
| **USB-C Connector** | J1, R1, R2 | Power input & data, CC pull-downs for host detection |
| **3.3 V LDO** | U1, C1–C3, LED1, R3 | Regulates 5 V VBUS → 3.3 V, power indicator LED |
| **USB-UART Bridge** | U2, C4 | CP2102N converts USB to UART for programming & debug |
| **Auto-Program** | Q1, Q2 | Cross-coupled NPN transistors toggle EN/IO0 from DTR/RTS |
| **ESP32 Module** | U3, C5–C7, R4–R5, SW1–SW2 | ESP32-WROOM-32E with strapping, reset & boot buttons |
| **GPIO Peripherals** | LED2, R6–R8 | User LED on IO2, strapping pull-ups on IO5 & IO15 |

## Block-by-Block Walkthrough

### 1. USB-C Connector (J1)

A USB Type-C receptacle provides 5 V power (VBUS) and data lines (D+/D−).
Two **5.1 kΩ pull-down resistors** on CC1 and CC2 are required by the USB-C
specification — they tell the upstream host that this device draws up to 500 mA
at 5 V (default USB power).

### 2. 3.3 V LDO Regulator (U1 — AMS1117-3.3)

The ESP32 runs at 3.3 V, so an **AMS1117-3.3** linear regulator steps VBUS
(5 V) down to 3.3 V. Key passives:

- **C1 (10 µF)** — Input decoupling, stabilises the regulator input.
- **C2 (22 µF)** — Output decoupling, required by the AMS1117 datasheet for
  stability.
- **C3 (100 nF)** — High-frequency bypass on the 3.3 V rail.
- **LED1 + R3** — Green power indicator (≈ 1.6 mA).

### 3. USB-UART Bridge (U2 — CP2102N)

The **CP2102N** converts USB to UART so you can program the ESP32 and read
serial output from a laptop. D+ and D− connect directly from the USB-C
connector. The UART side exposes TXD, RXD, DTR, and RTS.

### 4. Auto-Program Circuit (Q1, Q2)

Two **SS8050-G NPN transistors** form a cross-coupled latch that lets tools
like `esptool.py` automatically toggle **EN** (reset) and **IO0** (boot mode
select) using the DTR and RTS serial control signals — no manual button
pressing needed during firmware upload.

| Signal Flow | Effect |
| --- | --- |
| DTR low → Q1 on → EN pulled low | ESP32 resets |
| RTS low → Q2 on → IO0 pulled low | ESP32 enters download mode |

### 5. ESP32-WROOM-32E (U3)

The main module exposes all 31 pins of the ESP32 with proper strapping:

- **EN**: 10 kΩ pull-up (R4) + 1 µF power-on reset delay cap (C7) + RESET
  button (SW1).
- **IO0**: 10 kΩ pull-up (R5) + BOOT button (SW2). High = normal boot,
  low = download mode.
- **IO5 / IO15**: 10 kΩ pull-ups (R7, R8) for correct boot log behaviour
  (SDIO slave timing / debug output).
- **C5 (10 µF) + C6 (100 nF)**: Bulk + HF bypass on the 3.3 V supply close to
  the module.

### 6. User LED (LED2)

A blue LED on **IO2** with a 1 kΩ current-limiting resistor. GPIO2 is also an
SDIO strapping pin but is safely pulled low by the LED circuit at boot.
