`assembly.explosion.stage` names a step in an exploded assembly view. Put stages inside an [`assembly.device`](./assembly-device.mdx) or [`assembly.subassembly`](./assembly-subassembly.mdx), with one or more [`assembly.explosion.move`](./assembly-explosion-move.mdx) children.

## Lift the cover and bolts together

The first stage below lifts the cover and every part targeted by `remove-bolts`. The second stage then pulls the bolts farther out. The PCB stays fixed. The cylinders stand in for the two fasteners in this small example.

<CircuitPreview

    { name: "Lift cover and bolts", explosion: { throughStageRef: "case.lift-cover" } },
    { name: "Bolts halfway out", explosion: { throughStageRef: "case.remove-bolts", stageProgress: 0.5 } },
    { name: "Remove bolts", explosion: { throughStageRef: "case.remove-bolts" } },
  ]}
  defaultView="3d"
  hideSchematicTab
  wrapCode
/>

Targeting another stage selects its members; it does not execute that stage's instructions or change playback order. A stage can be referenced before its declaration, as `remove-bolts` is here.

## Stage properties

| Property | Description |
|----------|-------------|
| `name` | Required stage name, unique in its assembly scope. |
| `prevStageRef` | Stage that must finish before this one. |
| `nextStageRef` | Stage that must start after this one. |
| `children` | Ordered `assembly.explosion.move` elements. |

Ordering references resolve relative to the owning assembly. Use a qualified path, such as `case.remove-bolts`, when addressing another scope. Stages without ordering constraints follow stable depth-first TSX order. Unknown references, duplicate stage paths, ordering cycles, and cyclic stage membership are errors.

## Play the exported Circuit JSON

Core renders the assembled geometry and explosion program together:

```tsx
import { Circuit } from "@tscircuit/core"
import { CadViewer } from "@tscircuit/3d-viewer"
import Assembly from "./assembly"

const circuit = new Circuit()
circuit.add(<Assembly />)
await circuit.renderUntilSettled()
const circuitJson = circuit.getCircuitJson()

// The viewer only needs the generated JSON.
;<CadViewer circuitJson={circuitJson} />
```

In the 3D viewer, right-click and select **Advanced → Exploded view…**. Scrub the slider through each stage, use **Reset** to return to the assembled pose, or close the panel to restore it. Use the stage selector above to compare rendered poses, or click an image to rotate that pose. The full 3D viewer also supports continuous scrubbing.

The JSON contains `cad_explosion_stage` records with resolved order and explicit member IDs, plus `cad_explosion_move` records with targets and world-space translations. A live TSX tree or a separate exploded JSON file is not needed for playback.

Use the same supported core version for both the TSX imports and the `Circuit` renderer. A CLI that bundles an older renderer can build the assembled geometry while omitting the explosion records; check the exported JSON for both record types.

## Sample a stage or export each frame

```ts
import { getCircuitJsonAssemblyExplosion } from "@tscircuit/core"
import {
  convertCircuitJsonToGltf,
  getAssemblyExplosionFrames,
} from "circuit-json-to-gltf"

const halfway = getCircuitJsonAssemblyExplosion(circuitJson, {
  throughStageRef: "case.remove-bolts",
  stageProgress: 0.5,
})

for (const frame of getAssemblyExplosionFrames(circuitJson)) {
  const glb = await convertCircuitJsonToGltf(circuitJson, {
    format: "glb",
    explosion: frame.explosion,
  })
  // Save/render glb, keep one camera, and label it with frame.name.
}
```

`stageProgress` ranges from `0` to `1`, dividing the selected stage equally among its sequential moves. Earlier stages stay complete. Each evaluation starts from the original assembled positions, so backward scrubbing does not accumulate movement. Derived pose JSON omits the instructions to prevent applying them twice; keep the original document for further playback.

`getAssemblyExplosionFrames` returns the assembled frame and every completed stage in order. Each exported GLB is a static pose, not an animation track.

## Render explosion images in CircuitPreview

Pass `explosion={{ throughStageRef: "case.remove-bolts", stageProgress: 0.5 }}` for one pose, or `explosionStages` for a named image sequence:

```tsx
<CircuitPreview
  code={assemblyTsx}
  circuitJson={exportedCircuitJson}
  defaultView="3d"
  explosionStages={[
    { name: "Assembled" },
    { name: "Lift cover", explosion: { throughStageRef: "case.lift-cover" } },
    { name: "Remove bolts", explosion: { throughStageRef: "case.remove-bolts" } },
  ]}
/>
```

Each selected image and its rotatable model use the same pose. The image service accepts `explosion_stage` and `explosion_progress` for 3D PNG, SVG, and GLB output. Omit both for the assembled pose. See the [image service API](https://github.com/tscircuit/svg.tscircuit.com#assembly-explosion-images).

## Supported versions and limits

Use `@tscircuit/core` **0.0.2234+**, `circuit-json` **0.0.539+**, and `@tscircuit/3d-viewer` **0.0.637+**. Native GLTF stage export requires `circuit-json-to-gltf` **0.0.159+**.

Explosion moves currently translate mechanical CAD and reference surfaces. Targets containing PCB or cable geometry are rejected; rotation instructions and swept collision checks are not supported. Guide lines show the requested motion, not verified assembly clearance.
