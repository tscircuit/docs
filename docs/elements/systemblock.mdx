Use `systemblock` to show what a circuit does. Blocks describe functions, groups
organize subsystems, and connections identify interfaces. Core automatically
chooses block sizes, positions, routes, and label positions.

## Pages and groups

| Element | Required props | Optional props |
| --- | --- | --- |
| `systemblock.page` | `name` | `displayName`, `description`, `direction`, `children` |
| `systemblock.group` | `name` | `displayName`, `description`, `children`, PCB associations below |
| `systemblock.component` | `name` | `displayName`, `description`, PCB associations below |
| `systemblock.connection` | `from`, `to` | `name`, `label`, `kind`, `direction` |

Page `direction` accepts `right` (default), `left`, `down`, or `up`. Pages can
stand alone or appear inside a board or subcircuit. Groups can contain components,
connections, and nested groups; pages cannot be nested.

Give every page a unique name. Components and groups share a name scope across
their entire page, including nested groups. `displayName` is the visible label;
it falls back to `name`. `description` explains the block's purpose.

## Connections

`from` and `to` name components on the same page. Use names, such as `sensor`,
rather than pin selectors. Optional connection names must be unique within
their page. Connections do not create electrical traces or nets.

```tsx
<systemblock.connection from="supply" to="controller" kind="power" label="3.3 V" />
<systemblock.connection from="sensor" to="controller" label="I2C" direction="both" />
```

`kind` is `signal` (default) or `power`. Signal connections are solid blue;
power connections are dashed orange. Connection `direction` is `forward`
(default), `both`, or `none`, controlling arrowheads independently of page layout.
Parallel interfaces, feedback cycles, and self-loops are supported.

## Associate blocks with PCB components

Both components and groups accept these optional props:

| Prop | Meaning |
| --- | --- |
| `pcbComponentName` | One physical component name, such as `U1`. |
| `pcbComponentNames` | Several component names, such as `["U1", "C1", "C2"]`. |
| `pcbSubcircuitName` | Named PCB subcircuit in which to resolve component names; used alone, associates the whole subcircuit. |

```tsx
<systemblock.group name="power" displayName="Power supply" pcbSubcircuitName="power">
  <systemblock.component name="regulator" displayName="3.3 V regulator"
    pcbComponentNames={["U1", "L1", "C1", "C2"]} pcbSubcircuitName="power" />
</systemblock.group>
```

Use either the singular or plural component prop. Without `pcbSubcircuitName`,
names resolve in the page's owning subcircuit. Associations do not inherit from
groups, change placement, or create connectivity. Missing or ambiguous targets
are errors, and referenced PCB output must be enabled and present.

## Render an SVG

Requires `@tscircuit/core` 0.0.2261 or later and `circuit-to-svg` 0.0.455 or later.
The `tscircuit` package re-exports core's `systemblock` namespace.

```tsx
import { Circuit } from "tscircuit"
import { convertCircuitJsonToSystemSvg } from "circuit-to-svg"
import SystemOverview from "./system-blocks.circuit"

const circuit = new Circuit()
circuit.add(<SystemOverview />)
await circuit.renderUntilSettled()
const json = circuit.getCircuitJson()
const page = json.find((record) =>
  record.type === "system_block_page" && record.name === "overview")
if (!page || page.type !== "system_block_page") throw new Error("Missing overview")
const svg = convertCircuitJsonToSystemSvg(json, {
  systemBlockPageId: page.system_block_page_id,
  width: 1000,
})
```

Omit `systemBlockPageId` to render the first page. The Circuit JSON records already
contain resolved geometry in diagram millimeters, centered on the page with +X
right and +Y up. Group membership does not introduce relative coordinates.
Connections store `is_signal` and `is_power` flags and `label_anchor_center`.
