The `<panel />` element arranges multiple [`<board />`](./board.mdx) elements
in one manufacturing panel. It must be the root element, and only one panel
is allowed per circuit. Use [`<subpanel />`](./subpanel.mdx) for nested groups
of boards.

Panels can contain boards, subpanels, and traces. Place components inside a
board; place traces between boards directly inside the panel. Every panel or subpanel must contain at least one board,
either directly or through a nested subpanel.

## Example

This two-column grid repeats a power-indicator board four times. Each board
has a two-pin power header, a current-limiting resistor, a red LED, and a bypass
capacitor. Connect 3.3V to J1 pin 1 and ground to pin 2. The local autorouter
routes the connections independently on each board.

<CircuitPreview
  defaultView="pcb"
  hideSchematicTab
  code={`
const IndicatorBoard = ({ width = "20mm", height = "15mm" }) => (
  <board width={width} height={height} autorouter="auto-local">
    <pinheader name="J1" pinCount={2} pitch="2.54mm" pcbX={-6} pcbY={0} />
    <resistor name="R1" resistance="1k" footprint="0603" pcbX={0} pcbY={3} />
    <led name="LED1" color="red" footprint="0603" pcbX={5} pcbY={0} />
    <capacitor name="C1" capacitance="100nF" footprint="0603" pcbX={0} pcbY={-3} />

    <trace from=".J1 > .pin1" to=".R1 > .pin1" />
    <trace from=".R1 > .pin2" to=".LED1 > .anode" />
    <trace from=".LED1 > .cathode" to=".J1 > .pin2" />
    <trace from=".J1 > .pin1" to=".C1 > .pin1" />
    <trace from=".C1 > .pin2" to=".J1 > .pin2" />
  </board>
)

export default () => (
  <panel layoutMode="grid" col={2} boardGap="3mm" edgePadding="5mm">
    <IndicatorBoard />
    <IndicatorBoard />
    <IndicatorBoard />
    <IndicatorBoard />
  </panel>
)
`}
/>

The panel automatically sizes to 53mm × 43mm: two boards per axis, one 3mm
gap, and 5mm padding on each edge.

## Panel traces: a shared programmer

A trace placed directly inside `<panel>` can connect ports on different boards.
Prefix each port selector with its board name, such as
`".PROGRAMMER .SELECT_IO .TARGET1"` and `"board.TARGET1 .DEBUG .SWDIO"`.
The panel autorouter resolves these ports after arranging the boards, so the
connections follow the final grid positions. Traces inside a board still route
locally; panel traces carry the electrical connections between boards.

For example, keep one shared programmer connection on a reusable board at the
edge of the panel and route its programming signals to two target boards. This
example uses an external SWD probe connected to `PROBE` on `PROGRAMMER`.
`DEBUG` represents each target microcontroller's programming interface.

The center pin of each three-pin selector connects to the probe. Fit shunts from
`COMMON` to `TARGET1` on **both** `SELECT_IO` and `SELECT_CLK` to program the first
board; move both shunts to `TARGET2` for the second. The target signal branches
remain separate, while ground is shared. The removable shunts are not modeled
as permanent copper connections in this example.

<CircuitPreview

  code={`
const TargetBoard = ({ name }) => (
  <board name={name} width={20} height={18}>

      pinLabels={["SWDIO", "SWCLK", "GND"]}
      showSilkscreenPinLabels
    />
    <pcbnotetext text={name} pcbY={6} fontSize={1} />
  </board>
)

export default () => (
  <panel
    layoutMode="grid"
    col={3}
    boardGap={3}
    edgePadding={5}
    panelizationMethod="none"
    autorouter="auto-local"
  >
    <board name="PROGRAMMER" width={26} height={18}>
      <pinheader
        name="PROBE"
        pinCount={3}
        pcbX={-8}
        pinLabels={["SWDIO", "SWCLK", "GND"]}
      />
      <pinheader
        name="SELECT_IO"
        pinCount={3}
        pcbX={3}
        pcbY={4}
        pinLabels={["TARGET1", "COMMON", "TARGET2"]}
      />
      <pinheader
        name="SELECT_CLK"
        pinCount={3}
        pcbX={3}
        pcbY={-4}
        pinLabels={["TARGET1", "COMMON", "TARGET2"]}
      />
      <trace name="probe_data" from=".PROBE .SWDIO" to=".SELECT_IO .COMMON" />
      <trace name="probe_clock" from=".PROBE .SWCLK" to=".SELECT_CLK .COMMON" />
      <pcbnotetext text="Shared programmer" pcbY={-7} fontSize={0.8} />
    </board>
    <TargetBoard name="TARGET1" />
    <TargetBoard name="TARGET2" />
    {["TARGET1", "TARGET2"].map((target) => (
      <trace
        key={target + "_SWDIO"}
        name={target + "_SWDIO"}
        from={".PROGRAMMER .SELECT_IO ." + target}
        to={"board." + target + " .DEBUG .SWDIO"}
      />
    ))}
    {["TARGET1", "TARGET2"].map((target) => (
      <trace
        key={target + "_SWCLK"}
        name={target + "_SWCLK"}
        from={".PROGRAMMER .SELECT_CLK ." + target}
        to={"board." + target + " .DEBUG .SWCLK"}
      />
    ))}
    <trace
      name="programming_ground"
      path={[
        ".PROGRAMMER .PROBE .GND",
        "board.TARGET1 .DEBUG .GND",
        "board.TARGET2 .DEBUG .GND",
      ]}
    />

This is a programming-interconnect example, not a complete programmer or target
microcontroller circuit. Supply the target boards and connect the probe's voltage
reference and reset signals as required by your programmer and MCU. Select one
target at a time; ordinary SWD targets must not all drive the shared data line.

`panelizationMethod="none"` deliberately leaves continuous panel material under
these traces. If you add routed cutouts or mouse bites, leave intact tabs for the
connections and check the routed paths. Cutting the panel traces during separation
disconnects the programmer board from each target. The individual board schematics
remain separate; use the PCB view to see panel connections.

## Properties

Distances accept numbers in millimeters or strings such as `"5mm"`.

| Prop | Type | Description |
| --- | --- | --- |
| `width`, `height` | `string \| number` | Panel dimensions. In grid mode, omitted dimensions are calculated from the grid bounds plus edge padding. |
| `pcbX`, `pcbY` | `string \| number` | Position of the panel. |
| `layoutMode` | `"grid" \| "pack" \| "none"` | Defaults to `"none"` for manual placement. Use `"grid"` for automatic placement. `"pack"` is accepted by the props but does not currently perform automatic panel packing. |
| `row`, `col` | `number` | Number of grid rows or columns. If one is provided, the other is calculated from the number of children. |
| `cellWidth`, `cellHeight` | `string \| number` | Minimum grid cell dimensions. Larger boards can expand their row or column. |
| `boardGap` | `string \| number` | Spacing between grid cells and gap used for tab routing. Defaults to `tabWidth` (2mm). |
| `edgePadding` | `string \| number` | Panel margin used for grid sizing. Defaults to 5mm. |
| `edgePaddingLeft`, `edgePaddingRight`, `edgePaddingTop`, `edgePaddingBottom` | `string \| number` | Override `edgePadding` for an individual edge. |
| `panelizationMethod` | `"tab-routing" \| "none"` | Generate tab-routing cutouts and optional mouse bites. Defaults to `"none"`. |
| `tabWidth` | `string \| number` | Width used for routed cutouts. Defaults to 2mm. |
| `tabLength` | `string \| number` | Length of the uncut bridges between routed sections. Defaults to 5mm. |
| `mouseBites` | `boolean` | Add perforation holes when tab routing is enabled. Defaults to `true`. |
| `noSolderMask` | `boolean` | Prevent solder mask from being applied to the panel. Defaults to `false`. |

## Layout

With `layoutMode="grid"`, the panel positions its child boards and subpanels.
Manual `pcbX`/`pcbY` positions on child boards are ignored and produce a warning.
Component positions inside each board remain local to that board.

Without `row` or `col`, the grid uses the available space when both panel
dimensions are provided; otherwise it chooses a roughly square grid. When
setting both `row` and `col`, provide enough cells for all children.

For manual placement, use `layoutMode="none"`, provide panel dimensions,
and position each child with `pcbX` and `pcbY`. Multiple unpositioned children
produce a placement error. See the
[manual placement example](../guides/tscircuit-essentials/panelization.mdx#basic-panel-with-explicit-positions).

## Tab routing

Set `panelizationMethod="tab-routing"` to generate routed cutouts with
connecting tabs between boards. Set `mouseBites={false}` to keep the tabs
without perforation holes. Tab routing is disabled by default.

The generator may reduce tab dimensions for small boards.

See the [Panelization guide](../guides/tscircuit-essentials/panelization.mdx)
for complete examples of tab routing, manual placement, and nested panels.
