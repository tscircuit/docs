## Overview

`<schematicgraphic />` places an SVG graphic on a schematic sheet. Use it for
block diagrams, system overviews, legends, or other graphics that are easier to
author as SVG than as individual schematic primitives.

Place the graphic inside a [`<schematicsheet />`](./schematicsheet.mdx) to choose
its page. Provide at least one SVG source:

- `svgContent` for complete inline SVG markup.
- `imageUrl` for an SVG URL or project-relative static asset.
- Both when `imageUrl` should be the canonical source and `svgContent` should
  provide fallback content if a non-data URL cannot be loaded.

export default () => (

    <schematicsheet
      name="System Overview"
      displayName="System Overview"
      sheetIndex={0}

        width="120mm"

      />
    </schematicsheet>
  </board>

/>

`width` and `height` set the rendered bounds. They are independent and
optional, but specifying both gives the most predictable result.

## Load an SVG Asset

Use `imageUrl` for an SVG stored with the project or available at a URL:

```tsx
<schematicsheet name="Overview">
  <schematicgraphic
    imageUrl="/assets/system-overview.svg"
    width="160mm"
    height="80mm"
  />
</schematicsheet>
```

The referenced file must resolve to a complete SVG document. PNG, JPEG, and
other image formats are not supported by `<schematicgraphic />`.

## Provide Fallback SVG Content

When both sources are present, `imageUrl` remains the canonical asset. For a
non-data URL that cannot be loaded, Core uses `svgContent` as fallback markup.

```tsx
const fallbackSvg =
  '<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 40 20">' +
  '<rect width="40" height="20" fill="#e2e8f0" />' +
  "</svg>"

<schematicsheet name="Overview">
  <schematicgraphic
    imageUrl="/assets/system-overview.svg"
    svgContent={fallbackSvg}
  />
</schematicsheet>
```

## Props

| Prop | Type | Required | Description |
| --- | --- | --- | --- |
| `imageUrl` | `string` | One source required | Canonical SVG URL, data URL, or project-relative static asset. |
| `svgContent` | `string` | One source required | Complete SVG markup. It is the source when `imageUrl` is omitted and can be fallback content when both are supplied. |
| `width` | `distance` | No | Positive rendered width. |
| `height` | `distance` | No | Positive rendered height. |

## SVG Requirements

Inline and loaded SVGs should be complete standalone documents:

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 50">
  <!-- SVG contents -->
</svg>
```

Include the SVG namespace on the root element. If predictable sizing matters,
also provide a `viewBox` in the source and `width` and `height` props on
`<schematicgraphic />`.
